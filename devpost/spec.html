DAVE — Technical Spec

Status: draft

How This Works, In Plain Language

DAVE is a Next.js web app. The browser shows pages rendered by React. When data needs to be saved or AI agents need to run, the browser calls Next.js API routes. Those routes talk to Supabase (hosted Postgres) for storage and to OpenAI for AI reasoning. GitHub integration happens server-side via the GitHub REST API. The reviewer agent (Dwight) reviews committed code from a linked PR. Everything runs locally with npm run dev.

Stack

Next.js 16 · React 19 · TypeScript 5 · Tailwind 4 · Supabase · OpenAI · GitHub REST API · Radix UI · Zustand · @hello-pangea/dnd · cheerio · lucide-react

Where It Runs

Local: npm run dev → browser at http://localhost:3000. Requires .env.local with Supabase, OpenAI, and GitHub token keys. Demo recorded from browser. No deployment for POC.

Components

  • Auth — Login/role selection via Supabase Auth
  • Project Setup — Form for project details + GitHub repo URL
  • Team Builder — Human teammates + auto-seeded AI teammates
  • Kanban Board — 4 columns, drag-and-drop
  • Michael — AI task planner reading GitHub repo file tree
  • Jim — AI developer creating branches + PRs
  • Dwight — Reviewer agent reviewing committed PR code
  • Pam — Prior art search over public GitHub

Data Model

Supabase tables: projects, team_members, tasks, review_reports. Tasks are source of truth. Zustand holds transient UI state.

External Services

  • Supabase — Auth + Postgres (free tier)
  • OpenAI API — Agent reasoning (gpt-4o-mini)
  • GitHub REST API — Repo tree, branches, PRs, search (PAT auth, 5000 req/hr)

Important Failure Modes

  • GitHub token missing → agent features fail gracefully, rest works
  • OpenAI unavailable → agent endpoints error, UI shows "unavailable"
  • Supabase down → app shows error, no data loads
  • Empty/unreadable repo → Michael reports honestly, no invented files

What Was Simplified

  • Reviewer reviews committed code (not live Playwright)
  • GitHub uses PAT (not full OAuth)
  • Single-user demo (no real-time multi-user)
  • Reviewer results may be seeded/simulated where real execution isn't feasible
